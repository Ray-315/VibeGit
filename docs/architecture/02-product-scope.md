# B. 产品范围定义

## 1. 产品定位一句话

> 一个高颜值、现代化的本地 Git 可视化桌面工具，帮助开发者以图形界面完成日常 80% 的 Git 操作，并支持 GitHub 账号登录进行远程仓库管理。

---

## 2. MVP 必须做的功能（第一阶段交付）

### 2.1 仓库管理
- [x] 打开本地仓库（文件夹选择对话框）
- [x] 记住最近打开的仓库列表（最多 10 个）
- [x] 显示仓库基本信息（名称、路径、当前分支）
- [x] 初始化新仓库（`git init`）

### 2.2 状态与工作区
- [x] 显示工作区状态（已修改 / 已暂存 / 未跟踪文件列表）
- [x] 文件变更预览（diff 视图，支持文本文件）
- [x] Stage 单个文件 / 全部文件
- [x] Unstage 单个文件 / 全部文件
- [x] 丢弃工作区修改（Discard changes）

### 2.3 提交
- [x] 撰写 commit 消息并提交
- [x] 支持多行 commit 消息（subject + body 分离）
- [x] 显示当前 commit 的 author 信息（来自 git config）

### 2.4 分支管理
- [x] 显示本地分支列表
- [x] 切换分支（checkout）
- [x] 创建新分支
- [x] 删除本地分支（已合并）

### 2.5 提交历史
- [x] 显示提交历史列表（hash、消息、作者、时间）
- [x] 点击 commit 查看详情（文件变更列表 + diff）
- [x] 支持基础分页（虚拟列表，大仓库不卡顿）

### 2.6 UI 基础
- [x] 暗色主题（默认）
- [x] 三栏布局（侧边栏 / 主内容 / 详情面板）
- [x] 自适应窗口缩放（最小宽度 900px）
- [x] 高分屏适配（HiDPI / 100%~200% DPI）
- [x] 基础 loading / 错误提示状态

---

## 3. 明确的非目标（第一阶段不做）

以下功能在 MVP 阶段**不实现**，避免过度设计：

| 功能 | 排除原因 |
|---|---|
| GitHub OAuth 登录 / API 集成 | 复杂度高，独立为第二阶段 |
| Push / Pull / Fetch 远程操作 | 依赖凭证管理，第二阶段 |
| Merge / Rebase / Cherry-pick 操作 | 冲突处理 UI 复杂，第三阶段 |
| 冲突解决（三路合并视图） | 专业工具级别，延后 |
| Blame 视图 | 非核心日常操作 |
| 提交图谱（分支拓扑图） | 渲染复杂，第二阶段 |
| Stash 管理 | 较少使用，第二阶段 |
| Tag 管理 | 较少使用，第二阶段 |
| Submodule 支持 | 复杂度高，延后 |
| 多仓库工作区 | 超出 MVP 范围 |
| 团队协作 / PR 审查 | 第三阶段 |
| 插件系统 | 架构延后引入 |
| 终端集成 | 不在核心路径 |
| 文件夹树状工作区浏览 | 第二阶段 |
| 差异并排视图（side-by-side diff） | 第二阶段 |
| 语法高亮（diff 视图） | 第二阶段（可用 shiki） |
| 搜索/过滤 commit 历史 | 第二阶段 |
| 应用更新（自动升级） | 第二阶段 |

---

## 4. 第二阶段可扩展功能

### 4.1 GitHub 集成
- GitHub OAuth 登录（Device Flow，无需回调服务器）
- 显示远程仓库信息
- Push / Pull / Fetch 操作
- 克隆 GitHub 仓库
- 查看 PR 列表

### 4.2 增强 Git 操作
- Stash / Pop Stash
- Tag 创建与查看
- 分支提交图谱（DAG 拓扑视图）
- 并排 diff（side-by-side）
- 语法高亮 diff（基于 shiki）
- 搜索/过滤 commit 历史

### 4.3 增强 UI 体验
- 文件夹树状工作区浏览
- 拖拽分栏调整
- 多标签页（多仓库）
- 快捷键系统
- 命令面板（Command Palette，类 VS Code）
- 亮色主题切换
- 应用自动更新（tauri-plugin-updater）

---

## 5. 第三阶段进阶能力

- Merge / Rebase 操作 UI
- 冲突解决（三路合并视图）
- Blame 视图
- Interactive Rebase（拖拽排序提交）
- Worktree 支持
- Submodule 管理
- 团队协作（PR 审查、Review 评论）
- GitHub Actions 触发与状态查看
- 本地 Git Hooks 管理

---

## 6. 功能优先级矩阵

```
高价值 + 低复杂度（优先做）：
  状态查看、Stage/Unstage、Commit、分支切换、提交历史

高价值 + 高复杂度（第二阶段）：
  提交图谱、Push/Pull、语法高亮 diff

低价值 + 低复杂度（按需做）：
  Tag 管理、Stash 管理

低价值 + 高复杂度（不做或延后）：
  冲突解决、Interactive Rebase、Submodule
```

---

## 7. 用户故事（MVP 场景示例）

**场景 A：日常开发提交**
> 打开仓库 → 看到已修改文件 → 点击文件预览 diff → 勾选要提交的文件 → 输入 commit 消息 → 提交

**场景 B：切换分支**
> 侧边栏看到当前分支 → 点击分支列表 → 选择目标分支 → checkout 完成 → 自动刷新状态

**场景 C：查看历史**
> 点击提交历史标签 → 滚动浏览 commit 列表 → 点击某个 commit → 右侧显示变更文件和 diff
